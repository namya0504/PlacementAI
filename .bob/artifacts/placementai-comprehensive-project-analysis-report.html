2. Bug Report

Critical
BUG-01
Resume PDF URL becomes inaccessible after ~5 minutes

Root Cause: When generatePDF is called, a Supabase signed URL is created with expiresIn: 300 seconds (5 minutes) and stored in the Firestore resumes document as pdfUrl. On the next page load or login, getResumes reads this now-expired URL from Firestore and returns it to the frontend without refreshing it for records that have a storageProvider === 'supabase' but no storagePath.

Impact: Users see broken PDF links and cannot download or view resumes they generated earlier.

Fix: In getResumes, always re-generate the signed URL from storagePath (not from the cached pdfUrl) for all Supabase-backed records. See Section 4 for full analysis.

Critical
BUG-02
Uploaded profile resume disappears after ~1 hour

Root Cause: uploadProfileResume generates a signed URL with expiresIn: 3600 (1 hour) and stores it in the users document as resumeDownloadUrl. getProfileResume does refresh the URL on every call — but it only works if the caller hits that endpoint. If the frontend loads the profile data from the /me session endpoint instead of GET /api/profile/resume, it reads the stale stored URL.

Impact: After ~1 hour (or next login session), the "View Resume" link on the Profile page returns a 403/400 from Supabase.

Fix: Never persist the signed URL in Firestore. Store only storagePath and always generate fresh signed URLs on-the-fly at read time. Detailed fix in Section 4.

High
BUG-03
Dashboard shows hardcoded placeholder stats instead of real data

Location: src/pages/Dashboard.jsx lines 42–53.

Root Cause: The initial state for dashboardData contains hardcoded values (resumeScore: 87, atsScore: 87, ...). If the API.getDashboardStats() call fails silently (e.g. network error), users see fabricated scores rather than an error state.

Fix: Initialise stats to all-zero values or null; show a loading skeleton or error message if the fetch fails.

High
BUG-04
Resume Builder "Save as Profile Resume" fails silently when html2pdf is used

Location: src/pages/ResumeBuilder.jsx — handleDirectDownloadHtml2Pdf.

Root Cause: The catch block around html2pdf().from(element).set(opt).outputPdf('blob') falls through to a plain .save() without setting lastPdfBlobRef.current. The subsequent "Save as Profile Resume" banner still appears but clicking it shows: "No PDF available. Please use Direct PDF first."

Fix: Hide the banner if lastPdfBlobRef.current is null; or handle the error distinctly from the blob path.

High
BUG-05
Duplicate resume creation on every "Download" action

Location: src/pages/ResumeBuilder.jsx — handleDownloadPdf and handleDirectDownloadHtml2Pdf.

Root Cause: Both download handlers call API.saveResume(resumePayload) unconditionally when activeResumeId is not set (i.e. the first download). Clicking "Download PDF" and then "Direct PDF" creates two separate resume documents in Firestore for the same work session.

Fix: Track a single activeResumeId in state and always do an updateResume once the ID is set, regardless of which download method is called.

High
BUG-06
Role field in profile update allows privilege escalation

Location: backend/controllers/profileController.js — updateProfile.

Root Cause: The field role from req.body is written directly to the users collection (the authentication document). There is no whitelist of permitted role strings (only "student" or similar should be user-settable). A student can set role: "admin" and have it persist in Firestore.

Fix: For user-initiated updates, write targetRole (career goal) only and never allow overwriting the system role field.

Medium
BUG-07
Skills ID collision in createResume when multiple skills added quickly

Location: backend/controllers/resumeController.js lines 195–197.

Root Cause: Skill IDs use Date.now() inside a synchronous loop. If multiple skills are created in the same millisecond, the ID fragment is identical and only one Firestore document is written (upsert). Skills are silently dropped.

Fix: Append the loop index or use crypto.randomUUID() instead of Date.now().

Medium
BUG-08
ATS Checker "saved" mode triggers analysis before resumes load

Location: src/pages/ATSChecker.jsx — useEffect for searchParams (lines 96–104).

Root Cause: When a ?resumeId=... URL is present, handleAnalyzeSavedResume(resumeId) is called immediately. The saved resumes list is still loading, so savedResumes.find() returns undefined and the analysis is run with incomplete or missing context.

Fix: Gate the URL-driven analysis behind savedResumes being fully loaded, or add a loading guard.

Medium
BUG-09
Error stack trace exposed to clients in production

Location: backend/middlewares/errorHandler.js.

Root Cause: The guard is process.env.NODE_ENV === 'development', which is correct. However, if NODE_ENV is unset in the deployment environment, it defaults to 'development' and stack traces are returned to clients.

Fix: Default to production-safe behaviour: expose stack only when explicitly === 'development', never when the value is missing.

Low
BUG-10
Resume version history: saveWebResumeVersion off-by-one purge

Location: backend/controllers/profileController.js line 628.

Root Cause: The condition existingVersions.length >= MAX_RESUME_VERSIONS triggers when there are exactly 10 versions. It deletes the oldest to make room, but the slice math existingVersions.length - MAX_RESUME_VERSIONS + 1 evaluates to 1 when at exactly 10 — correct only for the first overflow. If called multiple times in rapid succession (e.g. multiple downloads at once), the counter is based on a snapshot, potentially leaving 11+ versions.

Fix: Enforce the limit after insertion by querying again, or use a Firestore transaction.

4. Resume Upload — Deep Dive & Persistence Fix

4.1 Current Implementation Workflow

PROFILE RESUME UPLOAD (src/pages/Profile.jsx → API → backend) ─────────────────────────────────────────────────────────────── User selects file → handleResumeUpload() → POST /api/profile/resume (multipart/form-data) → uploadMiddleware (Multer memoryStorage, 5 MB, MIME filter) → uploadProfileResume() ├─ validateFile() — size + MIME check ├─ validateFileSignature() — magic byte check ├─ generateStoragePath() — safe uid/subId/filename.ext ├─ deleteFile() — remove old file from Supabase if present ├─ uploadFile() — POST to Supabase Storage bucket "resumes" ├─ getSignedDownloadUrl(..., 3600) ← ⚠ URL expires in 1 hr └─ FirestoreHelper.setDoc('users', userId, { resumeStoragePath: "resumes/uid/subId/file.pdf", resumeDownloadUrl: signedUrl, ← ⚠ cached expired URL resumeUploadedAt: ... }, true) ← Returns { resumeDownloadUrl, resumeFileName, ... } PROFILE RESUME READ (getProfileResume) ─────────────────────────────────────── GET /api/profile/resume → reads users/{userId} → if resumeStorageProvider === 'supabase': regenerates signed URL → updates Firestore cache ✓ ← Returns fresh URL ✓ (only if this endpoint is called) RESUME BUILDER PDF STORAGE ─────────────────────────── generatePDF() → PDFService.generateResumePDF() → Buffer → uploadFile('resumes', storagePath, buffer) → getSignedDownloadUrl('resumes', storagePath, 300) ← ⚠ 5 MIN ONLY → FirestoreHelper.setDoc('resumes', resumeId, { pdfUrl: signedUrl, ← ⚠ cached; expires in 5 min storagePath: "resumes/...", storageProvider: 'supabase' }, true) RESUME LIST READ (getResumes) ────────────────────────────── GET /api/resume → queries resumes where userId === uid → for each: if storageProvider === 'supabase' && storagePath: getSignedDownloadUrl(bucket, storagePath, 3600) ✓ else: returns stored pdfUrl ← ⚠ May be stale for legacy records

4.2 Root Cause of Visibility Issues

ScenarioRoot CauseEffect
Profile resume after ~1 hr resumeDownloadUrl is a 3600-second signed URL stored in Firestore. If the user navigates to Profile without hitting GET /api/profile/resume first (e.g. navigated directly, cached data), the stale URL is used. 403 / expired URL error when clicking "View Resume".
Generated PDF after ~5 min generatePDF stores a 300-second URL as pdfUrl. getResumes does regenerate for Supabase-backed records, but only if storagePath is set. Any older record missing storagePath uses the stale pdfUrl. PDF link shows as broken in "My Resumes" panel.
After next login / ~2 days Session restore calls GET /api/auth/me, not GET /api/profile/resume. The signed URL in the returned user object has expired. User sees no download link or a broken one in the Profile page until they explicitly call the resume endpoint.
Frontend cache (15s TTL) api.js caches GET responses for 15 seconds. If getProfileResume is called twice in rapid succession, the second call returns a cached signed URL that may be close to expiry. Minor race condition; usually not user-visible.

4.3 Required Fixes

Fix A — Critical
Never store signed URLs in Firestore; always regenerate on read

In uploadProfileResume, remove resumeDownloadUrl from the Firestore write. Store only resumeStoragePath.

In getProfileResume, always call getSignedDownloadUrl with a generous TTL (e.g. 3600s) and return it without writing it back to Firestore.

In generatePDF, do the same — store storagePath only; never store pdfUrl as the primary retrieval key.

Fix B — High
Extend frontend signed-URL cache TTL to match backend TTL

In src/services/storageService.js, the in-memory signedUrlCache already caches for expiresIn - 30 seconds. Ensure the backend's expiresIn argument is always ≥ 3600 so cached URLs remain valid across a full user session.

Fix C — High
Load profile resume on every Profile page mount

In src/pages/Profile.jsx, the useEffect correctly calls API.getProfileResume(). Ensure the api.js cache TTL for this endpoint is either bypassed (add it to the skip-cache list like check-email) or kept very short (≤ 60 s). Add a "Refresh" button to the resume card for users who re-upload.

Fix D — Medium
Increase default signed URL TTL in generatePDF to 1 hour

Change getSignedDownloadUrl('resumes', storagePath, 300) → getSignedDownloadUrl('resumes', storagePath, 3600). This prevents immediate expiry for users who generate and then immediately try to open the PDF in a new tab.

5. Logic & Performance Improvements

5.1 Backend

IssueLocationRecommendation
N+1 Firestore reads in getResumes resumeController.js lines 51–66 For each resume, up to 3 sub-collection queries are made (skills, projects, certificates) only when arrays are empty. This is an N×3 read pattern. Denormalise data at write time (already done for new records) and add a migration to backfill old documents, eliminating the sub-queries entirely.
Sequential await inside skill/project/cert creation loops resumeController.js lines 192–215 Firestore writes are sequential; switch to Promise.all(). Also replace Date.now()-based ID generation with index suffix or crypto.randomUUID() (BUG-07).
In-memory rate limiter not shared across processes rateLimiter.js On auto-scaling or serverless deployments, each instance has its own map. Replace with a Redis-backed limiter (e.g. rate-limiter-flexible) for production correctness.
Duplicate route registration server.js lines 94–97 Routes are mounted at both /api/:path and /:path. The bare-path fallback should be removed or protected to prevent unintended route shadowing in production.
Missing Firestore indexes firestoreHelper.js Composite queries like queryCollection('resumes', 'userId', uid) require a Firestore index. Without it, reads fall back to full-collection scans in production. Add firestore.indexes.json with the required composite indexes.
PDF generation triggered per download — no caching resumeController.js — generatePDF Each generatePDF call re-renders the HTML template and generates a new PDF even if the resume data hasn't changed. Cache by resumeId + content hash, or generate only when the resume document's updatedAt is newer than the last PDF timestamp.
AI prompt input not sanitised against delimiter injection grokService.js While sanitizeUserInput() truncates text, it does not escape """ (triple-quote delimiters) or XML-like tags. Implement a structured message format that fully separates the system context from user-provided content.

5.2 Frontend

IssueLocationRecommendation
GET cache TTL (15 s) is too short for stable data api.js Profile and resume list data changes infrequently. A 15-second cache causes excessive re-fetching on every navigation. Use a per-endpoint configurable TTL: 15 s for scores/live data, 60 s for profile, 300 s for template lists.
Cache cleared on every mutation regardless of endpoint scope api.js line 51 getCache.clear() on any mutation drops all cached data. Scope invalidation: a resume save should only invalidate /resume cache entries, not profile or dashboard entries.
ResumeBuilder state not persisted between page navigations ResumeBuilder.jsx All form state is held in component-local useState. Navigating away and back resets the form. Add auto-save to sessionStorage or draft the resume to the backend every 30 seconds.
html2pdf generates a raster PDF (JPEG quality ~0.98) ResumeBuilder.jsx — handleDirectDownloadHtml2Pdf html2pdf rasterises the DOM to JPEG before embedding in PDF, resulting in blurry output at high zoom and large file sizes. Prefer the native print path (window.print()) or a server-side PDF generator (pdfService.js) for production-quality output.
Missing loading states on several async operations Multiple pages Profile avatar upload, GitHub scan, and ATS analysis do not always disable the triggering button during processing, allowing duplicate submissions.

6. UI/UX Improvements

All recommendations maintain the existing purple/slate/white colour scheme and Tailwind-based design system.

6.1 Global / Cross-page

IssueRecommendationPriority
No global toast/notification system Replace scattered alert() calls (≥ 8 occurrences) and local success/error message strings with a centralised toast component (e.g. a lightweight custom hook). alert() is synchronous and blocks the UI thread. High
Loading skeletons absent for data-heavy sections Add shimmer/skeleton placeholders for Dashboard stats cards, Resume list, and ATS scan result while data loads — prevents layout shift and improves perceived performance. High
Error boundaries not present Wrap page-level components in React ErrorBoundary so a failed render in one widget (e.g. broken resume template) doesn't crash the entire app. Medium
No keyboard navigation / accessibility audit Tab order, ARIA labels, and focus management are inconsistent. Add aria-label to icon-only buttons, ensure modals trap focus, and add role="alert" to dynamic error messages. Medium
Mobile sidebar z-index conflicts On small screens, the mobile sidebar occasionally renders behind modals. Standardise z-index scale: sidebar 40, modal overlay 50, modal 60, toast 70. Low

6.2 Dashboard

IssueRecommendation
Hardcoded placeholder stats (BUG-03) Replace with zero-state designs: empty bar charts, "Not attempted yet" copy, and CTAs pointing to the relevant module.
Progress rings are static SVG; no animation Animate ring stroke-dashoffset from 0 to the value on mount. This adds visual polish without additional dependencies.
Study plan tasks have no visual due-date indicator Add a small date chip or "Due today" label to high-priority tasks.

6.3 Resume Builder

IssueRecommendation
No auto-save indicator Add a subtle "Saved ✓" / "Unsaved changes" indicator in the header. Users frequently lose work due to accidental navigation.
Template preview is hidden behind a button Show a thumbnail grid of templates on Step 1 so users can select their template before filling in data, reducing mid-flow context switching.
Validation errors appear only at Step 3 Show inline per-field validation as users type and highlight the incomplete tab in the navigation bar with a red dot, giving earlier feedback.
Download methods (Print / Direct PDF) are confusing to users Merge into a single "Download PDF" button. Use the server-side PDF endpoint as primary; fall back to html2pdf if unavailable. Remove the dual-button confusion.

6.4 Profile Page

IssueRecommendation
Resume section shows no feedback while loading signed URL Add a loading spinner and "Refreshing link…" text while getProfileResume is in flight.
AI Insights modal opens automatically on resume upload This is jarring. Instead, show a non-blocking banner: "We extracted skills from your resume — review them?" with a single CTA to open the modal.
Skills section in edit mode has no drag-to-reorder Allow reordering by drag-and-drop or up/down arrows so users can prioritise top skills.

6.5 ATS Checker

IssueRecommendation
Scan mode tabs ("Upload / Saved / Profile") are not visually distinct when disabled Grey out "Profile Resume" mode with a tooltip "No resume uploaded yet — go to Profile to upload" when profileResume.hasResume is false.
Score radial is rendered as plain text percentage Render as an animated SVG arc gauge (matching Dashboard style) for visual consistency.
