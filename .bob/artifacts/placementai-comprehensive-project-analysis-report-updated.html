2. Bug Report

10
✓ All Bugs Fixed
0

Regressions
Critical
BUG-01
Resume PDF URL becomes inaccessible after ~5 minutes
✓ Fixed

Root Cause: generatePDF stored a 5-minute Supabase signed URL as pdfUrl in Firestore. On next load, getResumes returned the expired URL.

Impact: Broken PDF links in "My Resumes" panel after ~5 minutes.

✓ generatePDF no longer writes pdfUrl to Firestore. Only storagePath + metadata stored. URL TTL raised to 3600 s. getResumes regenerates fresh signed URLs from storagePath on every read.
Critical
BUG-02
Uploaded profile resume disappears after ~1 hour
✓ Fixed

Root Cause: uploadProfileResume stored a 1-hour signed URL as resumeDownloadUrl in Firestore. Stale URL served on subsequent logins.

Impact: "View Resume" link returns 403/400 after ~1 hour or on next login.

✓ resumeDownloadUrl no longer written to Firestore. getProfileResume always regenerates a fresh URL from resumeStoragePath — no Firestore write-back. /profile/resume endpoint bypasses the 15 s API cache.
High
BUG-03
Dashboard shows hardcoded placeholder stats instead of real data
✓ Fixed

Root Cause: Initial state had hardcoded values (resumeScore: 87, atsScore: 87, …). Silent API failures showed fabricated scores.

✓ All initial stats set to 0. statsLoading / statsError states added. Score values guard with statsLoading ? 0 : …. Hardcoded fallbacks || 87, || 76 in derived values also removed.
High
BUG-04
Resume Builder "Save as Profile Resume" fails silently on html2pdf error
✓ Fixed

Root Cause: On blob generation failure, the catch block fell through to plain .save() without setting lastPdfBlobRef.current. The banner appeared but clicking it showed an unhelpful error.

✓ Catch block now sets lastPdfBlobRef.current = null explicitly. Banner is only shown when blob capture succeeds.
High
BUG-05
Duplicate resume created on every "Download" action
✓ Fixed

Root Cause: Both download handlers called API.saveResume() when activeResumeId was unset, even within the same session — creating two Firestore documents for identical work.

✓ Both handleDownloadPdf and handleDirectDownloadHtml2Pdf now use if (activeResumeId) to update rather than create whenever an ID is already set, regardless of URL params.
High
BUG-06
Role field in profile update allows privilege escalation
✓ Fixed

Root Cause: updateProfile wrote role from req.body directly to the users auth document with no whitelist. A student could set role: "admin".

✓ System role field is never written from user input. Only targetRole (career goal) is user-editable. The updateProfile response returns userDoc.role (unchanged system role) to the frontend.
Medium
BUG-07
Skill/project/cert ID collision in createResume
✓ Fixed

Root Cause: IDs used Date.now() in a synchronous loop — same millisecond = same ID = silent Firestore upsert overwrites. Skills silently dropped.

✓ All IDs now use crypto.randomUUID(). Loop converted to Array.map() + Promise.all() for parallel writes.
Medium
BUG-08
ATS Checker "saved" mode triggers analysis before resumes load
✓ Fixed

Root Cause: ?resumeId=… URL parameter triggered handleAnalyzeSavedResume() immediately, before the saved resumes list had finished loading.

✓ savedResumesLoaded flag added. URL-driven analysis effect depends on [searchParams, savedResumesLoaded] — analysis fires only after the list is ready.
Medium
BUG-09
Error stack trace exposed to clients when NODE_ENV is unset
✓ Fixed

Root Cause: Inline process.env.NODE_ENV === 'development' guard defaults to true if the env var is absent, leaking stack traces in production.

✓ Extracted to const isDevelopment = process.env.NODE_ENV === 'development'. Unset env now defaults to production-safe behaviour (no stack trace).
Low
BUG-10
Resume version history off-by-one purge
✓ Fixed

Root Cause: Sequential for loop + snapshot-based count could leave 11+ versions when called concurrently.

✓ Purge now uses Promise.all(toRemove.map(…)) for parallel deletes and correctly calculates excessCount = existingVersions.length - MAX_RESUME_VERSIONS + 1.
